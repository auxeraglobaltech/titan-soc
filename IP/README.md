# IP — block-level DV playground

Each folder here is one OpenTitan IP: the real RTL, the real spec, and a
testbench that does nothing. **Building the verification environment is the
exercise.**

> Track plan, decisions and risks: [`docs/IP_WORK.md`](../docs/IP_WORK.md).
> The other track is [`docs/SOC_WORK.md`](../docs/SOC_WORK.md) (chip-level DV).

---

## Quick start

```bash
source scripts/activate_env.sh     # bash
source scripts/activate_env.csh    # csh/tcsh
which xrun

cd IP/uart/sim
./run_compile.sh --print           # show the xrun command, run nothing
./run_compile.sh                   # elaborate + run uart_base_test
less runs/compile.log
```

Expect `uart_base_test ... compile check complete -- TEST PASSED` and
`UVM_ERROR : 0`. That is the *starting* line, not an achievement — the test
checks nothing.

> ⚠️ **One simulation at a time** — the server is shared. Check `who` first.

## Available IPs

| IP | Source tree | Tier | Elaborates | Env built | Why pick it |
|---|---|---|---|---|---|
| [`gpio`](gpio/) | `ip_autogen/` | starter | ✅ | 🔲 | Simplest. No protocol — checking is "did the pin do what the register said" |
| [`pwm`](pwm/) | `ip_autogen/` | starter | ✅ | 🔲 | Small register file, no interrupts, but **two clock domains** |
| [`uart`](uart/) | `hw/ip/` | intermediate | ✅ | 🔲 | First real serial protocol; 9 interrupts; FIFOs and watermarks |
| [`i2c`](i2c/) | `hw/ip/` | intermediate+ | ✅ | 🔲 | Open-drain bus, controller **and** target mode, 15 interrupts |
| [`spi_host`](spi_host/) | `hw/ip/` | intermediate+ | ✅ | 🔲 | 3 data widths × 4 clock modes; segmented commands |
| [`rv_plic`](rv_plic/) | `ip_autogen/` | advanced | ✅ | 🔲 | 186 sources; needs a model-based scoreboard, not directed tests |

**Suggested first pick**: `gpio` if you have never built a UVM environment,
`uart` if you have. `rv_plic` last — it is the one where a directed-test
approach genuinely does not work.

More IPs are scaffolded with [`scripts/new_ip.sh`](scripts/new_ip.sh); see the
execution plan in [`docs/IP_WORK.md`](../docs/IP_WORK.md#5-execution-plan).

## What is deliberately missing

`verification/` has no agent, driver, monitor, scoreboard, sequencer, RAL or
coverage. That is not an oversight. Upstream ships a complete DV environment
for every one of these IPs and copying it in would delete the exercise.

If you are genuinely stuck, the upstream environment is at
`vendor/opentitan/hw/ip/<ip>/dv/` (or
`vendor/opentitan/hw/top_earlgrey/ip_autogen/<ip>/dv/`). Read it *after* you
have attempted the piece yourself, or you will learn nothing.

**Also withheld on purpose**: `data/<ip>_testplan.hjson` upstream. Writing the
testplan from the spec is step 2 of the exercise; check yours against theirs
afterwards.

## The exercise

1. **Compile.** `./run_compile.sh`. Confirm clean elaboration before changing
   anything, so you know any later error is yours.
2. **Read.** `docs/theory_of_operation.md`, `docs/registers.md`,
   `docs/interfaces.md`, and the linked spec. Enumerate every feature.
3. **Plan.** Write `verification/testplan.md` — feature, test, pass criteria,
   coverage goal. Follow the format in [`testplan/README.md`](../testplan/README.md).
4. **Build.** TL-UL host agent (reuse `hw/dv/sv/tl_agent`), RAL generated from
   `docs/<ip>.hjson`, an IP-specific agent for the pins, a scoreboard.
5. **Test.** Write to the testplan. Close functional coverage.

Suggested order for step 4: get a register read/write working end-to-end first
(that proves agent + RAL + scoreboard connectivity in one go), then the
protocol pins, then interrupts, then error and alert cases.

## Gotchas already paid for

- **Abstract prims.** `prim_flop`, `prim_flop_2sync`, `prim_clock_gating` are
  *not* in `prim/rtl/` — FuseSoC resolves them to `prim_generic/rtl/`. Both are
  in `common/rtl/`; drop either and elaboration fails on unresolved modules.
- **Package order.** `common.f` lists packages explicitly before modules
  because `tlul_pkg` scope-resolves into `top_pkg`/`prim_secded_pkg`, and
  `top_racl_pkg` into `tlul_pkg`. Do not alphabetise it — regenerate with
  `scripts/gen_common_f.sh`.
- **Never leave an input floating.** Tie unused DUT inputs to a constant. An X
  propagating into a register file trips the TL-UL `dKnown` assertions and the
  failure surfaces long after the actual cause (chip track lost a cycle to
  this — `docs/XCELIUM_NOTES.md` quirk #14).
- **Not every prim is generic.** 14 files in `prim/` and `tlul/` belong to a
  specific IP and need that IP's package (`prim_lc_*` need `lc_ctrl_pkg`,
  `prim_edn_req` needs `edn_pkg`, ...). They are excluded from `common.f`. If
  your IP needs one, add it plus its package to your own `rtl/files.f` — see
  [`common/README.md`](common/README.md).
- **Cross-IP dependencies happen.** `spi_host` will not compile without
  `spi_device_pkg`, because its passthrough port is typed from it. Use
  `scripts/new_ip.sh --extra-rtl <path>`; do not widen `common.f`.
- **The RTL here is a copy** taken at OpenTitan `365c167e`. If
  `vendor/opentitan` is ever bumped, `IP/` does not follow. Re-copy
  deliberately.
- **`*W,SPDUSD` is expected.** "Include directory given but not used" — the
  filelists declare incdirs that a bare compile-check does not consume. Left in
  deliberately, because you *will* need them once you add `.svh` files. It is
  the only warning any of these six IPs produces.
